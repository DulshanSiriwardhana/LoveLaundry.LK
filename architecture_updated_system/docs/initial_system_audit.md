### 3.1 Authentication **[V]**
- JWT, algorithm **HS256**, secret from `JWT_SECRET` (fatal if unset). Payload keys
  observed: `auth_id`, `role`, `status`, `user_name`, `exp`, `iat`.
- `get_current_user` (`user-service/src/user_service/auth_helper.py:63`) cryptographically
  verifies the token, then **reloads the user** via `repository_factory.get_repository()` →
  `get_by_auth_id(auth_id)`:
  - missing account → `401 "Account no longer exists."`
  - status in `DISABLED_STATUSES = {inactive, disabled, suspended, blocked, deleted}` →
    `403 "This account has been deactivated..."`
  - live `role_id` and `status` overwrite the token claims (demotion takes effect next request).
- `require_role([...])` returns a dependency enforcing `payload["role"] in allowed_roles`
  (case: roles are upper-cased on refresh).

### 3.2 Crypto **[V]** (`love-ai/src/crypto_helper.py`, mirrored in other services)
- `KEK = sha256(MASTER_KEY + "-kek")`, `HMAC_KEY = sha256(MASTER_KEY + "-hmac")`.
- Envelope encryption: per-document random 256-bit DEK, values encrypted with
  AES-256-GCM, DEK wrapped with `KEK`; stored under `encryption_metadata`
  (`algorithm: AES-256-GCM`, `keyId: master-key-v1`, `wrappedDek`).
- Deterministic `get_search_token(value)` = `HMAC-SHA256(HMAC_KEY, normalize(value))` for
  exact-match search over encrypted PII; `*_search` fields stripped on decrypt.
- `hash_api_key()` (HMAC), `constant_time_equal()` (`hmac.compare_digest`).
- Request signing: `sign_request(api_key, method, path, timestamp, body_hash)` over a
  canonical `"\n"`-joined string; `verify_request_signature(...)`.
- `canonical_json()` = `json.dumps(sort_keys=True, default=str, separators=(",", ":"),
  ensure_ascii=False)` — **must** match quotations-ui `config/ai.ts` and skaner
  `core/utils/idempotency.dart`.
- **Critical coupling [I]:** `MASTER_KEY` must be **identical across services** or encrypted
  fields written by one service cannot be read by another (e.g. love-ai decrypting
  laundry-management PII) and search tokens will not match.

### 3.3 Database architecture **[V]** (`bill-service/src/bill_service/database/connection_manager.py`)
- Three logical roles, each with its **own** client and `(uri, db_name)`:
  - `MAIN` — production source of truth (all normal reads/writes).
  - `SECONDARY` — verification replica, written **only** by the sync worker.
  - `LOCAL` — admin-triggered replica; never an API read source.
- Resolution falls back to legacy `MONGO_URI` / `DATABASE_URL` and `MONGO_DB_NAME`.
- **[I]** `user-service` additionally has a SQLAlchemy path (`models.py` defines ORM
  `User`; `postgresql_repository.py` + `repository_factory.py` choose backend from
  `DATABASE_URL`). Bill-service's connection manager uses **motor** (async); other
  services may use sync `pymongo` (prior-session note).

## 8. Known risks / findings carried from the prior hardening pass **[V]**

These were fixed in the prior session (now baseline, listed so the recreation preserves the
corrected behavior):

1. `bill-service` billable-delivered basis: availability clamped to received qty via
   `compute_billable_delivered_by_name()` (`services/balance_engine.py`).
2. `laundry-management` reports: expense decryption raw-field fallback +
   transaction-derived summaries.
3. `user-service`: `_id` stripped before `$set`; token revocation reloads user; disabled
   statuses centralised.
4. `quotation-service`: sync worker starts in `startup_event` (skipped under `ON_VERCEL`);
   `_norm_qid()` returns 404 for non-numeric ids on SQL backends; chat IDOR closed.
5. `worker-service`: SQLite `PRAGMA table_info` migration; group label recompute.
6. `love-ai`: canonical JSON for `data_hash` (matches TS/Dart clients).
7. Frontends: client-pub `react-icons` dependency declared + lockfile; public site deps.

Open risks for the recreation to preserve/avoid:

- **Committed `.env` secrets** (rotation is an operator action).
- **`.gitmodules` wrong `path=`** entries for some services (git uses gitlink paths).
- **Stray nested clones** in `worker-service/`.
- **Duplicate directory** `system-managment/`.
- **Cross-service coupling** on identical `MASTER_KEY` / `JWT_SECRET`.
- **monitoring/load-testing**: no load test exists; **no evidence for "1,000 concurrent
  users"** — that number must not appear in any deliverable until a real load test is run.

## 10. Recreation scope (honest size assessment) **[I]**

The original comprises **~420 route decorators across 6 Python services**, 6+ frontends,
a Node bot, and a Flutter app, plus a 3-database replication/sync layer and a shared crypto
platform. Full endpoint-for-endpoint parity is a multi-stage effort. This project proceeds
in the staged plan (`docs/architecture_decisions.md`, `docs/current_checkpoint.md`) and
records verified progress per stage rather than claiming completion.
